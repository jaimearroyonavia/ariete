topic: Ariete: Rail agent for autonomous error diagnosis, remediation, and remote infrastructure management with human approval
updated: 2026-10-05T12:46
---

- (decision) Why: fills 24/7 support gap using internal RAG knowledge base to reuse known solutions, reduce MTTR, protect customer reputation and app uptime
- (capability) Public URL monitoring (uptime-robot style) detects timeouts, connectivity failures, DNS issues, app errors via logs, crashed services (MySQL, Nginx, PHP)
- (capability) Remote diagnostics: analyzes logs and service state to propose root cause and remediation (e.g., 'PHP-FPM needs spare processes', 'disk full - DB cannot write')
- (capability) Human-in-the-loop approval: operator reviews and approves proposed fixes via widget UI on any device, no direct host SSH needed
- (capability) Autonomous mode for off-hours (e.g., nights) with guardrails: execute fixes without approval under constraints
- (decision) Stack: Rails app + Redis + Sidekiq (queues) + PostgreSQL; remote SSH/similar to managed infrastructure; internal RAG for knowledge base
- (constraint) Security is primary concern due to remote command execution; agent must authenticate, authorize, and audit all actions
- (decision) Admin section: user creates account, adds domains, configures infrastructure and remote connection details per domain
- (decision) RAG: PostgreSQL with pgvector extension for embeddings storage; reuse same DB, avoid separate vector DB operational overhead
- (decision) Success signal: MTTR reduction, autonomous fix rate (% incidents resolved without human), uptime improvement, oncall page reduction, Ariete actions/week
- (constraint) Non-goals (v1): read-only on customer data, no infra scaling (no new VMs/containers), no permanent code/config changes, no backup management
- (event) Self-validate pass 1 (coherence): all 6 capabilities have intent + success, intents describe WHAT not HOW, constraints bend design, non-goals explicit, success signal is concrete and testable. Spec law 1-6,8 pass.
- (event) Self-validate pass 2 (preservation): all user input claims preserved in SPEC (monitoring, diagnostics, approval, autonomous mode, RAG, security, admin, PostgreSQL+pgvector, Rails+Redis+Sidekiq). No wrapper-ceremony.
- (event) Spec finalized. 6 capabilities, 4 constraints, 5 non-goals, 5 success metrics, 3 open questions.
